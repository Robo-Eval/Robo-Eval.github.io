CoRL 2026 · Challenge Suite · Track 2

RoboEval Diagnostic Bimanual Challenge

Binary success rates hide how a bimanual policy fails. This challenge asks you to build policies that are not just successful but well-behaved — coordinated, efficient, safe, and robust to spatial variation — and scores them with stage-level diagnostics rather than a single pass/fail bit.

Part of the CoRL 2026 Embodied AI Benchmark and Sim-to-Real Challenge Suite, hosted at the workshop From GPU-Accelerated Simulation to Scalable and Generalizable Real Robot Policy Learning — November 12, 2026, Austin, Texas, USA.

04

Why This Challenge Is Different

In our study, policies with nearly identical success rates diverged sharply in how they executed the same task — some lost alignment, others lost temporally consistent bimanual control. Behavioral metrics correlated with success in over half of all task–metric pairs, and stayed informative even where binary success saturated. This challenge is built around that finding.

Stage-level diagnosis

Every task decomposes into skill-specific stages, so a failure is localized to where it happened — not just recorded as a zero.

Systematic variation

Each task is evaluated on its combined position + orientation variant, so object poses change in every episode and a policy must generalize spatially rather than memorize a fixed scene.

Coordination is scored

Arm velocity mismatch and gripper height offset are first-class metrics, so genuinely bimanual behavior is rewarded over two arms acting independently.

Safety counts

Collisions, slips, and jerk are measured throughout. A policy that succeeds by flailing through the scene will not win.

Tasks & Data

The challenge uses the RoboEval task suite: everyday bimanual activities drawn from service, warehouse, and industrial settings, each paired with expert demonstrations and stage annotations. The challenge evaluates every task family on its PR (combined position and rotation) variant; demonstrations from all variants listed below may be used for training.

Demonstration data

Over 3,000 human demonstrations, collected through VR teleoperation on an Oculus Quest and through keyboard teleoperation, are released as a ready-to-train LeRobot dataset, roboeval_ee_delta_20hz_scaled: 3,060 episodes over all 30 variants at 20 Hz, with end-effector delta actions, five 256×256 cameras, proprioception, and a language instruction per episode. See Getting Started to download and load it. You may use all of it, a subset, or none of it.

Observation & action interface

Actions are joint positions or end-effector poses, absolute or delta, for both arms plus grippers, applied at 20 Hz, with the same joint speed limit in every mode. Observations are proprioception (joint positions and velocities, gripper state) plus RGB and/or depth from any of five cameras: external, head, front, and one on each wrist. You declare the combination in your submission and the evaluator runs exactly that.

How You Are Scored

Submissions are ranked by the RoboEval Diagnostic Score, which combines four metric families: outcome 40%, safety & stability 30%, efficiency 20%, and bimanual coordination 10%. Behavior is scored against human demonstrations of the same task and counts in proportion to how often the policy succeeds, so a policy that does nothing scores 0. The evaluator prints your score. The formula is in Ranking and the metric definitions are in the Metrics Reference.

Outcome

  • Success (SR)
  • Task Progression (TP)

Efficiency

  • Cartesian Path Length (CPL)
  • Joint Path Length (JPL)
  • Orientation Path Length (OPL)
  • Completion Time (CT)
  • Trajectory Length (TL)

Coordination

  • Bimanual Arm Velocity Difference (BAVD)
  • Bimanual Gripper Vertical Difference (BGVD)

Safety & Stability

  • Self Collision Count (SCC)
  • Environment Collision Count (ECC)
  • Slip Count (SC)
  • Mean Joint Jerk (MJJ)
  • Mean Cartesian Jerk (MCJ)

Getting Started

  1. Install RoboEval Clone the repository, check out the challenge release, and install into a clean Python 3.10 environment. 
    git clone https://github.com/Robo-Eval/RoboEval.git
cd RoboEval
git checkout corl2026-challenge
git submodule update --init

conda create -n roboeval python=3.10 -y
conda activate roboeval
pip install -e ".[examples]"
  2. Verify the installation Run the evaluator on two episodes with the template policy. It needs no display and finishes in under a minute. 
    export MUJOCO_GL=egl   # on machines without a display
python -m roboeval.challenge.evaluate --submission examples/challenge_submission \
    --tasks LiftPot --episodes 2 --output-dir /tmp/roboeval_check --overwrite

    With a display attached, python examples/1_data_replay.py also opens the viewer and replays human demonstrations. Its first run downloads about 1.8 GB of demos.

  3. Explore the tasks and data Instantiate an environment and inspect the observation and action interface. 
    import numpy as np
from roboeval.envs.lift_pot import LiftPotPositionAndOrientation
from roboeval.action_modes import JointPositionActionMode
from roboeval.robots.configs.panda import BimanualPanda
from roboeval.utils.observation_config import CameraConfig, ObservationConfig

env = LiftPotPositionAndOrientation(
    # end-effector delta actions, as in the released dataset
    action_mode=JointPositionActionMode(absolute=False, ee=True,
                                        floating_base=True, floating_dofs=[]),
    observation_config=ObservationConfig(
        cameras=[CameraConfig(name="head", resolution=(256, 256))]),
    render_mode=None,          # "human" opens a viewer and needs a display
    control_frequency=20,
    robot_cls=BimanualPanda,
)
obs, info = env.reset(seed=1000)
obs, reward, terminated, truncated, info = env.step(np.zeros(env.action_space.shape))
print(obs.keys(), info["subtask_progress"])
  4. Get the training data and train The demonstrations are a LeRobot (v3.0) dataset with one sub-dataset per task variant. The position + orientation variants that are evaluated total about 31 GB; all 30 variants are about 102 GB. Current lerobot needs NumPy 2 while RoboEval pins NumPy 1.26, so train in a separate environment from the one you evaluate in. 
    python3.11 -m venv train-env && . train-env/bin/activate
pip install lerobot "huggingface_hub[hf_transfer]"

# the 8 evaluated variants (~31 GB); drop --include for all 30 (~102 GB)
hf download helen9975/roboeval_ee_delta_20hz_scaled --repo-type dataset \
    --include "*PositionAndOrientation/*" --local-dir roboeval_data
    from lerobot.datasets.lerobot_dataset import LeRobotDataset

ds = LeRobotDataset("LiftPotPositionAndOrientation",
                    root="roboeval_data/LiftPotPositionAndOrientation", revision="local")
frame = ds[0]   # cam_head, cam_front, cam_external, cam_left_wrist, cam_right_wrist,
                # state (36), state_gripper (2), actions (14), task (instruction)

    The dataset matches the template submission's interface (end-effector delta actions at 20 Hz). At evaluation time your policy receives rgb_<camera> images (3×H×W, uint8) for the cameras you declare, proprioception (the dataset's state), proprioception_grippers (state_gripper), and the task's instruction. Train with any framework (for example LeRobot's policies or openpi), on these demonstrations, your own data, or any pretraining; see the rules for what is and is not permitted.

  5. Run the evaluation Copy the template bundle, point policy/policy.py at your model, declare your interface in metadata.yaml, and run all 8 tasks on the official seeds. 
    cp -r examples/challenge_submission ~/submission
python -m roboeval.challenge.evaluate --submission ~/submission --workers 16 --gpus 0
  6. Submit Add your technical report, then validate and package the bundle and submit the link. Full instructions are on the Submission Guidelines page. 
    python -m roboeval.challenge.package ~/submission

Hardware note

RoboEval runs on Linux with MuJoCo. Proprioception-only policies evaluate on CPU; camera observations are rendered on an NVIDIA GPU through EGL. VR teleoperation for collecting your own demonstrations additionally requires an Oculus Quest and GLIBC 2.32+.
